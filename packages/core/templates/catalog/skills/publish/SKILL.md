# Publish

Before publishing: every skill it names exists, it reaches for categories
rather than vendors, it has a stated path with nothing connected, and its
standards live in playbooks rather than baked into the prompt.

Attach an eval set with cases whose correct answers are known, including
the edge cases found during testing. That set is what makes the definition
safe to change later.

Write the description so somebody browsing knows in one line whether this is
for them.

Where it will be shared, say plainly what it can reach and what it can do
unattended. A definition that writes or sends, running for somebody who did
not build it and does not know its assumptions, is a real hazard.
