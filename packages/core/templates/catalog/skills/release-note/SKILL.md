# Release Note

Lead with what somebody can now do that they could not before. Not the
component that changed.

Say who it is for. A reader should know within one line whether this
affects them.

State anything that requires action: changed behaviour, something removed,
a migration, a setting that needs revisiting. Bury none of it — an
unannounced behaviour change is discovered as a fault.

Written in the reader's vocabulary, not the codebase's. Where a fix is
included, describe the symptom they experienced rather than the cause.
