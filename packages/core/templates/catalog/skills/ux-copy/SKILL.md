# UX Copy

Write from the reader's side of the screen. Name things as they recognise
them, not as the system implements them.

**Controls say what happens.** A button labelled with its outcome, and
confirmation that matches the label.

**Errors** say what went wrong, and what to do about it. No apology, no
blame, no error code as the whole message. If it cannot be fixed by the
reader, say who can.

**Empty states** say what goes here and how to get the first one. An empty
state is the first thing many people see.

Specific beats clever. Read every string aloud — anything that sounds
strange spoken is strange written.
