## Symptom

`GET /v1/events` returning 500 for roughly 4% of requests since
2026-09-05 08:50Z. Errors are concentrated on requests with a `page`
parameter above 400.

## Impact

Two customer integrations paging deep history are retrying. No data
loss observed. A workaround exists: request a narrower date range.

## Timeline

- 08:50Z — error rate rises from 0.1% to 4%.
- 09:12Z — alert fires, incident opened.
- 09:30Z — database CPU normal; the errors correlate with query time on
  deep offsets, not with load.

## Open questions

Whether PR-1841 (cursor pagination, not yet merged) would remove the
class of failure entirely, or whether the deep-offset query needs an
index today.
