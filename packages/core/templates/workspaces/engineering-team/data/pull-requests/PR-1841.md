Replaces offset pagination on `GET /v1/events` with an opaque cursor.
`?page=` is still accepted for one minor version and returns a
deprecation header.

Adds a `next_cursor` field to the response envelope. Existing clients
that ignore unknown fields are unaffected.

Notes for the reviewer: the cursor encodes `(created_at, id)` and is
base64 of a JSON object. No index change was needed — the existing
composite index covers it. No test yet for the case where a row is
deleted between pages.
